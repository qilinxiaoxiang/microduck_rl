# CMU MicroDuck layer on the microduck_rl fork — design

Date: 2026-10-19. Problem advanced: P5/P6 bring-up and the project goal in `microduck-sim/PROJECT-CONTEXT.json`
(camera-guided pickup learned in simulation and transferred to the robot). Evidence that would change the decision:
a teammate cannot reproduce the as-built sim check or train the as-built variant from a fresh clone.

## Decision

Reuse the existing GitHub fork `qilinxiaoxiang/microduck_rl` (fork of `pollen-robotics/microduck_rl`) instead of a new
repository. Branch `main` = Pollen's `develop` (b02fdea, 2026-10-12) plus one added layer, `cmu/`, and three small
hooks into Pollen's tree (task registration, `.gitignore`, optional dependency group). Branch `develop` stays a
pure mirror of upstream so `git merge develop` brings Pollen's updates in.

Why a fork and not a new repo: teammates get Pollen's whole recipe (mjlab envs, BAM actuators, the 61-input
contract, velstand, pickup detector, publish) with one `uv sync`, and our layer is visibly the delta. Why one
layer directory: everything that is specific to the CMU robot (masses, sole, sensor path, runtime, real logs,
fine-tune pipeline, sim-real findings) is in one place and can be refreshed from the private robotics working
tree with one script.

## Layout of `cmu/`

- `README.md` — index and the three quickstarts (CPU sim check on this robot's model; train/fine-tune the as-built
  variant on a GPU, Kaggle T4 or Modal L4; close the loop in the pickup simulation).
- `ROBOT.md` — what differs from Pollen's duck and why it matters for sim: head computer (Radxa Cubie A7Z, the
  policy runs on the MacBook today), two power forms (bench "plugged" box without lid; 2S battery backpack),
  wrapped anti-slip sole, servo rail 7.0 V while walking, KP 200 walking / 400 stand, sensor path (BNO085 at
  50 Hz over J12 UART, about 4 % dropped servo reads while stepping), runtime (`walk_wired.py`, no action filter).
- `SIM2REAL.md` — the measured gap with evidence and what was tried: trunk gyro jitter 4-6x the sim (broadband
  5-25 Hz), servo amplitude ratio 0.17-0.45 vs 0.24-0.75, yaw-rate spikes before falls, servo deadband at KP 200,
  Pollen robotd differences (0.9 action scale, target low-pass, coast on drops), failed remedies (runtime EMA,
  breakaway push in walk mode, ft1/ft2 fine-tunes), ft3 result, open hypotheses and how to test one.
- `robot-condition.json` — the sim-relevant current facts copied from `microduck-sim/CURRENT-STATE.json` with their
  verification dates (servo rail, IMU rate, drop fraction, added delay, deployed policy). `sim_suite.py` reads it.
- `model/` — `variants/{plugged,battery}.json` (delta part lists on top of the 2026-10-15 as-built manifest),
  `make_variants.py` (writes the full manifests), `apply_masses.py` (one function shared by the sim check and the
  training variant; CLI writes `scene_plugged.xml` / `scene_battery.xml` with explicit inertials for any MuJoCo
  tool), `sole/` (sweep and template).
- `mac/`, `pi/`, `whole/` — copies of the robotics working tree: Mac runtime and sim check
  (`guide/firmware/mac`), Pi-side constants and guards (`guide/firmware/pi`), and the whole-robot studies and
  policies (`hardware-design-20260912/whole-robot-20260912`: as-built manifest, real-gap study, delay repair,
  runtime overlay with walk61 / stand61 / groundpick61 and the ft3 candidate). The copies are generated by
  `sync_from_robotics.py` with recorded rewrite rules (path hops, no venv re-exec, relative manifest paths) and
  are never hand-edited in the fork.
- `simcheck/sim_suite.py` — the eight-case as-built suite (real cases from `robot-condition.json`, stress cases
  reported only) on any ONNX directory; the acceptance tool for a candidate policy before a robot test.
- `real-logs/robot-runs-20261018/` — four real runs at the robot's current condition (20 ms tick rows, same shape
  as the sim tick log), with the README that says what happened in each.
- `finetune/modal/`, `finetune/kaggle/` — the walk61 fine-tune pipeline (reward audit gate, tracking guard, cost cap,
  as-built masses, registered deltas) and its Kaggle launcher.

Hooks into Pollen's tree: `src/mjlab_microduck/tasks/cmu_asbuilt.py` + three lines in `tasks/__init__.py`
register `Mjlab-Velocity-Flat-MicroDuck-CMU-Plugged` and `-CMU-Battery` (Pollen's velocity recipe on the as-built
masses); `.gitignore` un-ignores `cmu/**/*.onnx`; `pyproject.toml` gains the optional group `cmu`
(opencv-python-headless, pyserial) for the pickup and runtime scripts. Tests: `tests/test_cmu_asbuilt_cfg.py`.

## Mass configurations

Base: `asbuilt-mass-manifest.json` (2026-10-15: V1.8 prints, V1.9 rear pack, bench box without lid, Pi Zero W head,
audio), applied to Pollen's MJCF bodies as signed parts with the NP-F970 battery (90 g) removed.

- `plugged` = base with the Pi Zero W (9.3 g) replaced by the Cubie A7Z at the same position (mass unpublished,
  bounded 15-20 g on 2026-10-19; entered as 18 g, labelled estimate) and the AC019 antenna (1.5 g estimate) in
  the cap. Bench box stays (two XL4015, 5991, frame, no lid).
- `battery` = plugged minus the bench box parts (frame, two XL4015, 5991, their screws and the 15 V / 7 V leads)
  plus the battery backpack items from the 2026-10-15 plan (`bp_mass.json`: frame 16.05 g, cap 8.05 g, Tattu 2S
  650 43 g, switch 14 g, DFR1202 6 g, plugs and leads 10 g), labelled plan estimates until weighed.

Whole-robot COM shift against Pollen's model is reported by `make_variants.py` for both.

## Verification

- `uv run cmu/mac/brain_sim_check.py --model asbuilt --volt 7.0 --drop 0.04 --vx 0.25` runs on a Mac CPU from a
  fresh clone (no `~/.venvs/microduck-dyn`), reproducing the walk61 result recorded in `SIM2REAL.md`.
- `uv run cmu/simcheck/sim_suite.py cmu/whole/runtime-overlay/models out.jsonl` writes eight rows.
- `uv run --with pytest pytest tests/test_cmu_asbuilt_cfg.py cmu/mac` passes on CPU.
- `uv run cmu/model/apply_masses.py --variant battery` writes a scene XML that compiles and reports the mass and COM.
- Kaggle launcher `pack --dry-run` stages the tarball with the new asset paths.
- The repository is pushed to `origin main`, default branch set to `main`, README renders on GitHub.

Out of scope: solving the jitter gap (an open problem documented for the next study); CAD, printing and
procurement material (stays in the robotics repo and the team guide site); robot-side board setup scripts.
